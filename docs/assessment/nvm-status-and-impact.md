## 1. Verdict

On this DUT, **NVM is healthy and the stored correction/calibration tables are in active use**. `$ME` returns `0000`. With `$CX 1` (power-on default), Stage 3 emission scans completed without `0111`, which implies a valid excitation correction table is present. Wavelength and slit *positioning* work over RS-232; **optical wavelength accuracy (`±1.0 nm`) remains unvalidated** until Gate D and reference standards.

`$ME` reports integrity only. There is **no RS-232 command to dump table coefficients**.

## 2. What NVM Stores

The User's Guide states that excitation correction factors and slit/monochromator calibration data are held in non-volatile memory, with internal backup copies. Service/calibration commands rewrite those tables; routine measurement commands only consume them.

| Stored content | Written / regenerated by | Consumed when | Failure / warning codes |
| --- | --- | --- | --- |
| **Excitation correction table** (rhodamine quantum-counter curve, ~230–630 nm) | `$CR` (correction table generation) | `$CX 1` (default); applied after block averaging / ratioing | Scans / time drive return **`0111`** if `$CX 1` and no valid table (`txt ~3805–3806`, `pp. 142`) |
| **Excitation monochromator wavelength calibration** | `$XC` (+ `$CT` continue) | `$GM`, `$SC`, `$WS` (loads cal into motor software) | Bad cal → systematic peak shift; shipping-clamp power-on can leave ~**14 nm** error (`txt ~616–620`) |
| **Emission monochromator wavelength calibration** | `$MC` (+ `$CT`) | Same as Ex mono | Same class of wavelength error |
| **Excitation slit calibration** | `$XS` | `$SX` bandpass commands (calibrated `2.5–15.0 nm`) | Slits below `2.5 nm` are uncalibrated (`0` → `<2 nm`) |
| **Emission slit calibration** | `$MS` | `$SM` bandpass commands (calibrated `2.5–20.0 nm`) | Same |
| **Backup copies of the above** | Internal firmware | Automatic recovery path | `$ME` **`0108`** recovered from backup; **`0106`** fatal |

Calibration dialogues use multi-step codes (`1000` / `1001` / `1002`) and **overwrite** stored tables. Do not invoke `$CR`, `$MC`, `$XC`, `$MS`, `$XS`, or `$WS` during routine automated tests ([../reference/serial-protocol.md](../reference/serial-protocol.md) §2).

### 2.1 Not stored as NVM “payload” (volatile / power-on defaults)

Live session parameters read during identity dumps are **not** the contents `$ME` validates. They reset or re-home at power-on and are set over RS-232 as needed:

- Excitation / emission wavelengths (`$GM` / `$ST`): DUT defaults `365.0` / `435.0` nm  
- Slit widths (`$SX` / `$SM`): `10.0` nm  
- Filter wheel (`$FW`): `7` (clear)  
- Data mode (`$PH`): `0` (fluorescence)  
- Scan speed / response, phosphorescence gate/delay, flash count  
- Excitation shutter (`$ES`): power-on default **ON** (`0`) — host must force OFF before opening the compartment  

Accessory presence (`$AF`) is detected at power-on / warm start; serial number (`$SN`) and mains frequency (`$HZ`) are identity queries, not calibration tables.

## 4. Operational Impact

### 4.1 Intensity scale (excitation correction)

With `$CX 1` and a valid NVM table, sample and reference channels are block-averaged, ratioed, and multiplied by the stored rhodamine curve to correct reference-photodiode / beamsplitter response over roughly **230–630 nm**. Consequences for this lab:

- Absolute and relative intensities across the excitation range depend on the stored curve. Disabling correction (`$CX 0`) changes reported levels and band shapes where Ex varies.
- **Emission** grating and PMT response are **not** fully corrected in firmware; host-side emission correction remains a planned software feature ([../software/features-and-roadmap.md](../software/features-and-roadmap.md) §3).
- If NVM correction data were lost while `$CX 1` remained set, quantitative scans would fail with **`0111`** rather than silently returning uncorrected data.

### 4.2 Wavelength scale (monochromator calibration)

NVM wavelength tables define the mapping from stepper position to reported nm. Impact:

- Correct `$GM` / `$SC` abscissae for peak ID, Raman shift, and sync scans.
- Corrupted or clamp-compromised cal produces a roughly fixed offset (manual cites ~14 nm after powered shipping clamps)—peaks look sharp but wrong.
- `$WS` reloads valid calibration into motor software; it returns `0106` / `0108` if NVM is bad.
- Stage 2 only verified **commanded vs. readback** agreement, not optical accuracy against lines or standards.

### 4.3 Bandpass, SNR, and auto PMT (slit calibration)

Calibrated `$SX` / `$SM` values assume NVM slit tables. Impact:

- Resolution and etendue (and thus water Raman SNR claims) track commanded bandpass only if slit cal is sound.
- Firmware couples **preset PMT voltage** to excitation slit; `$PV` readback `775 A` reflects that path in auto mode.
- Uncalibrated narrow slits (`0` / below `2.5 nm`) are explicitly out of the calibrated range.

### 4.4 Host and operator policy

| `$ME` code | Meaning | Recommended action |
| --- | --- | --- |
| `0000` | NVM OK | Normal operation; still validate optics after Gate D |
| `0108` | Recovered from backup | Preserve logs; re-check wavelength and slit cal before quantitative work |
| `0106` | Fatal NVM fault | Abort; hardware / service required; `$WS` will also fail |

Identity and Stage 1 harnesses already treat `0106` as a hard error and `0108` as a warning ([`ls55/identity.py`](../../ls55/identity.py), [`ls55/stage1.py`](../../ls55/stage1.py)).

## 5. What Remains Unproven

| Claim | Status |
| --- | --- |
| NVM integrity (`$ME`) | **Proven** `0000` on recorded dumps |
| Presence of usable excitation correction table | **Inferred** (`$CX 1` + scans without `0111`) |
| Numeric correction / cal coefficients | **Not readable** over RS-232 |
| Wavelength accuracy `±1.0 nm` | **Open** — needs Gate D + `$XC`/`$MC` peaks or external standards |
| Slit optical bandpass vs. commanded nm | **Open** — positioning verified; spectral width not measured |
| Water Raman sensitivity `500:1` | **Open** — requires holder + distilled-water method |
